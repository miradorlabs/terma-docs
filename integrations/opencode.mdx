OpenCode reads its OpenTelemetry settings only from environment variables, so there is no configuration file Terma could point at its endpoint. Instead, Terma installs a plugin: a single dependency-free JavaScript file that OpenCode loads at startup. The plugin turns OpenCode's events — sessions, prompts, tool calls, and each assistant message with its model, provider, tokens, and cost — into OpenTelemetry and sends them to Terma.

## Set up

```bash
terma connect opencode
```

On a terminal, `connect` shows a checklist of what to send. It writes the plugin to `~/.config/opencode/plugins/terma.js` (or under `$XDG_CONFIG_HOME/opencode`). Your `opencode.json` is never touched, and the project key never sits in the plugin — it fetches its authorization header from a Terma helper script.

To remove it:

```bash
terma disconnect opencode
```

## How it works

- **Telemetry.** The plugin converts OpenCode's plugin events to OTLP and posts them to Terma, including tokens and cost for each assistant message.
- **Attribution.** The plugin hands session start and end and every file edit to `terma hook`, so commits in an installed repository are stamped with OpenCode's sessions, the same way as other agents.
- **Repository policy.** A repository can narrow what is sent with a committed `.opencode/terma.json`, which the plugin lays over its global settings. It says only which signals ship and whether prompt and tool content go with them — never where or with which key — so it is safe to commit. Write it with `terma connect opencode --scope local`.

## What's captured

| Signal | Available |
|---|---|
| Sessions and turns | Yes |
| Model calls, provider, tokens, and cost | Yes |
| Tool calls, with arguments and output | Unless `--exclude-tool-content` |
| Prompts and responses | Unless `--exclude-prompts` |
| Files edited, for commit attribution | Yes |

## Verify

```bash
terma harness status opencode   # what OpenCode is configured to send
terma doctor                     # proves hooks stamp a commit and events reach Terma
```

`terma update` refreshes the plugin to the new version's template automatically.
