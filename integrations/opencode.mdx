<Info>
  **Coming soon.** OpenCode appears as **Coming Soon** in the `terma setup` agent picker, and you can't connect it yet. This page describes what Terma will capture once it is available. Today, `terma setup` connects [Claude Code](/integrations/claude-code) and [Codex](/integrations/codex).
</Info>

OpenCode reads its OpenTelemetry settings only from environment variables, so there is no configuration file Terma could point at its endpoint. Instead, Terma will install a plugin: a single dependency-free JavaScript file that OpenCode loads at startup. The plugin will turn OpenCode's events — sessions, prompts, tool calls, and each assistant message with its model, provider, tokens, and cost — into OpenTelemetry and send them to Terma.

## How it works

- **Telemetry.** The plugin converts OpenCode's plugin events to OpenTelemetry, including tokens and cost for each assistant message.
- **Attribution.** The plugin hands session start and end and every file edit to terma's hooks, so commits in a collected repository are stamped with OpenCode's sessions, the same way as other agents.
- **Policy.** As with every agent, your team's collection policy decides which repositories are collected and whether prompts and tool content leave your machine.

## What's captured

| Signal | Available |
|---|---|
| Sessions and turns | Yes |
| Model calls, provider, tokens, and cost | Yes |
| Tool calls, with arguments and output | When your team's policy collects tool content |
| Prompts and responses | When your team's policy collects prompts |
| Files edited, for commit attribution | Yes |
