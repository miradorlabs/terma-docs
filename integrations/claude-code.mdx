Claude Code is fully supported: Terma receives its usage and cost through Claude Code's own OpenTelemetry export, attributes the commits it produces through repository hooks, and reads your plan's usage windows through its status line.

## Set up

Run `terma install` in the repository, choosing **Claude Code** when asked (or record it once with `terma setup`):

```bash
cd your-repo
terma install --harness claude
```

Then reload your shell as `install` tells you (for zsh, `source ~/.zshrc`), commit the files it lists, and restart any running Claude Code sessions so they load the new configuration.

## How it works

Terma combines three channels.

### Telemetry: Claude Code's OpenTelemetry export

Claude Code exports its own traces, events, and metrics. `terma install` points that export at the repository's Terma project by handing Claude Code a per-repository settings document through `claude --settings`. The routing is delivered by a small `claude` shim that `install` puts first on your `PATH`, so running `claude` in this repository reports to this repository's project, and running it elsewhere reports wherever that repository points.

The project key never appears in a settings file. Claude Code fetches its OTLP headers from a helper script in `~/.config/terma/helpers/` at startup.

This channel carries model calls with their token counts (input, output, cache read, cache write) and cost, tool calls, and — unless you turn them off — your prompts, Claude's responses, and tool input and output.

### Attribution: repository hooks

`install` adds Terma's hooks to the repository's `.claude/settings.json`, which you commit:

| Hook | What Terma records |
|---|---|
| `SessionStart` | The session begins, with its account details |
| `PostToolUse` (matcher `Edit\|Write\|MultiEdit\|NotebookEdit\|Agent\|Task`) | The files each session edits, used to stamp commits, and subagent calls |
| `Stop`, `StopFailure` | A turn ended, or ended on an error such as a rate limit |
| `SubagentStart`, `SubagentStop` | Subagents the session spawns, and how each run went |
| `SessionEnd` | The session ends; queued events are delivered |

Each entry is a guarded one-liner:

```json .claude/settings.json
{
  "hooks": {
    "SessionStart": [
      {
        "hooks": [
          {
            "type": "command",
            "command": "command -v terma >/dev/null 2>&1 && terma hook session-start || true",
            "timeout": 10
          }
        ]
      }
    ]
  }
}
```

Hooks never read what was said — prompts, tool content, and transcripts reach Terma only through Claude Code's own export, under the settings you chose. On a machine without Terma, the hooks do nothing. Your existing hooks in the file are preserved.

### Plan usage: the status line

To capture your Claude plan's usage windows, `install` places `terma hook statusline` in front of your existing status line command in `~/.claude/settings.json`. Your renderer keeps running unchanged — its output is preserved byte for byte, prefixed by a small `t` marker. If you had no status line, Terma captures silently and shows nothing.

Skip this with `terma install --no-statusline`. If your renderer is slow, set `TERMA_STATUSLINE_TIMEOUT=60s` in Claude Code's environment.

## What's captured

| Signal | Source |
|---|---|
| Sessions, turns, and subagents | Hooks and OpenTelemetry |
| Model calls, tokens, and cost | OpenTelemetry |
| Tool calls and their duration | OpenTelemetry |
| Prompts and responses | OpenTelemetry, unless `--prompts off` |
| Tool input and output | OpenTelemetry, unless `--exclude-tool-content` |
| Files edited, for commit attribution | Hooks |
| Plan usage windows and rate limits | Status line and hooks |

## Controlling what is sent

- `terma install --prompts off` stops prompt text and model responses for this project.
- `terma install --exclude-tool-content` stops tool parameters, input, and output.
- `terma install --signals traces,metrics` limits which signals are exported.

A repository can also narrow what is sent for everyone who works in it with a committed local policy — see [Repository-local policy](/cli/harnesses#repository-local-policy).

## Verify

```bash
terma status    # the Agent line should show Claude Code exporting to this project
terma doctor    # proves hooks stamp a commit and events reach Terma
```

<Warning>
  An IDE extension that starts Claude Code by its full path bypasses the `claude` shim and uses your machine-wide settings. `terma doctor` reports when routing is not active. Claude Code's managed settings and a custom `--settings` argument are outside what Terma can check.
</Warning>
