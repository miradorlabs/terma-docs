Cursor's IDE and its `agent` / `cursor-agent` CLI share project hooks in `.cursor/hooks.json`. Terma uses those hooks for commit attribution and for an ordered record of each conversation. Cursor has no telemetry export Terma can use, so support is **partial**: attribution is complete, but cost, plan, and quota data are unavailable.

## Set up

In a repository you have already installed Terma in:

```bash
terma install --adapters cursor
```

Commit the updated `.cursor/hooks.json`. Your existing Cursor hooks and their options are preserved, and `terma uninstall` removes only Terma's entries.

## Hooks

| Hook | What Terma records |
|---|---|
| `sessionStart`, `sessionEnd` | Conversation boundaries |
| `beforeSubmitPrompt`, `afterAgentResponse`, `stop` | Ordered turn observations, with the selected model and optional token snapshots |
| `preCompact` | Context occupancy before compaction |
| `afterFileEdit` | Files edited, for commit attribution |
| `postToolUse`, `postToolUseFailure` | Every finished tool call |
| `subagentStop` | Subagents the conversation spawned, with their files |

`subagentStart` is deliberately not wired: it is a permission gate, and a hook that prints nothing would deny the spawn on a machine without Terma.

## What's captured

| Signal | Available |
|---|---|
| Commit attribution | Yes |
| Conversations, turns, and ordering | Yes |
| Selected model and Cursor version | Yes |
| Tool calls | Yes |
| Subagents | Yes |
| Token counts | Optional snapshots, when Cursor supplies them |
| Cost, plan, quota, and billed amount | No |
| Prompt and response text | No — hooks never read it |

<Note>
  Token values from Cursor's hooks are snapshots, not a complete ledger of model requests, and are not enough to compute exact cost. When Cursor runs in **Auto** mode, the selected model is not necessarily the model that was billed.
</Note>

## Privacy

Terma's Cursor hooks do not read or forward prompt or response text, messages, edit contents, error text, transcript paths, or credentials. Cursor may supply the signed-in account email; when it does, Terma includes it as personal metadata.

## Verify

```bash
terma harness list cursor   # what Terma supports for Cursor
terma doctor                # proves hooks stamp a commit and events reach Terma
```
