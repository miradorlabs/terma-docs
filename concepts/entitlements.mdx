Most engineers pay for AI in more than one way: a Claude or ChatGPT subscription for interactive work, a metered API key for scripts, prepaid credits on a router. The same tokens cost very different amounts depending on which one paid for them. Terma records how each account is funded, so it can show both what your usage would cost at list price and what it actually adds to your bill.

## Funding modes

Every account an agent uses has one of these funding modes:

| Mode | What it means | What Terma shows |
|---|---|---|
| **Subscription** | A plan with a usage allowance, such as Claude Max 20x or a ChatGPT plan | The plan name, and each allowance window — for example **5-hour** and **7-day** — with how much is used and when it resets |
| **Prepaid credits** | A balance that usage draws down | The credit balance |
| **Metered** | Pay-per-token billing with no allowance, such as an API key | List price, no cap |
| **Funding unknown** | Terma has no evidence of how the usage was paid for | Usage and list price only |

A person can have several accounts for one source; each is shown separately on their [Users](/dashboard/users) page.

## Cost views

A **Usage view** control on the dashboard switches between three ways of counting, and your choice applies across every page:

| View | What it counts |
|---|---|
| **Tokens** | Reported input, output, cache-read, and cache-write tokens, including usage without a price. It measures volume, not cost. |
| **Notional** | The gross list price of every generation — what a metered API would charge for all of it. This is the default. |
| **Net** | Notional minus the spend a subscription allowance already covers, so it reads as the marginal bill. Metered, prepaid, and unattributed usage stay in both. |

The difference between Notional and Net is how much your subscriptions absorbed. The Overview shows that split directly, as the share of spend covered by subscription.

## Where funding evidence comes from

Terma learns how usage is funded from the agents themselves, when Terma is installed with the CLI:

- **Claude Code** — the signed-in account and plan, read at session start, and the plan's allowance windows, read through Claude Code's status line. See [Claude Code](/integrations/claude-code#plan-usage-the-status-line).
- **Codex** — the plan, its primary and secondary allowance windows, and credit balances, read by Terma's Codex hooks.

When the effective credential is an API key rather than the subscription login, Terma does not attribute the usage to the subscription.

If people run an agent without the Terma CLI, their allowance windows are **unobserved** and their usage is **Funding unknown**. The Overview shows a funding gap banner naming how many people that affects.

<Note>
  Cursor and Antigravity hooks do not report plan, quota, or billed cost, so their usage is never classified as subscription-covered.
</Note>

## How usage is priced

- **Sources that report cost** — Claude Code's telemetry, for example, or the amount OpenRouter charged — are used as reported.
- **Everything else** is priced from Terma's catalog of list prices, per model and provider. Session costs priced this way are marked **Estimated** (or **Partly estimated**) in the dashboard.

**Settings → Connections** lists each telemetry source and whether it reports cost.

Each model's page shows its current list prices by provider and their history. See [Models](/dashboard/models).

## From the CLI

`terma usage` reports the provider's cost for each model call that settled in the window — the same basis as the **Notional** view.

```bash
terma usage --since 30d --group-by provider
terma usage --since 30d --group-by api-key   # spend on API keys, such as OpenRouter keys
```
