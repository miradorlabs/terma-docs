Terma connects three things that usually live apart: what your coding agents did, what it cost, and the code it produced. This page introduces the pieces and how they fit together.

## Organizations and projects

An **organization** is your team's workspace. Members, invitations, roles, the GitHub connection, and principal mapping belong to the organization.

A **project** is where activity lands. Each repository is bound to one project by `terma install`, and every session, usage figure, and attributed commit from that repository reports there. Use separate projects for separate products or teams.

Your CLI sign-in is scoped to an organization, not a project, so you can work across repositories that report to different projects without signing in again.

## Sources

A **source** is anything that sends telemetry to a project:

- **Coding agents** — Claude Code, Codex CLI, and Codex Desktop, set up per repository by `terma install`. Cursor, OpenCode, and Antigravity have partial or advanced support.
- **Routers and other tools** — OpenRouter, or any tool that exports OpenTelemetry, sending with a project [server key](/dashboard/settings#server-keys).

## Sessions

A **session** is one conversation with an agent, rolled up with its turns, model calls, tool calls, tokens, cost, subagents, and Git activity. Sessions are what everything else is built on.

## Principals

Sources report identities, not people: an email seen by Claude Code, a user id seen by Codex, an API key seen by OpenRouter. Each of these is a **principal**. Organization admins map principals to members, so one person's activity across every agent rolls up as that person.

## Attribution

Terma's `prepare-commit-msg` hook stamps each commit with `Agent-Session-Id` and `Agent-Tool` trailers for every session that edited a staged file. Pure human work gets no trailer. The link lives in your Git history, and with the GitHub connection, Terma lines up pull requests with the sessions behind them.

## Funding and cost

The same tokens cost different amounts depending on whether a subscription, prepaid credits, or a metered key paid for them. Terma records how each account is funded and tracks subscription allowance windows, so you can view usage as **Tokens**, at list price (**Notional**), or as the marginal bill after subscriptions (**Net**).

## How data flows

<Steps>
  <Step title="Agents export, hooks record">
    Each agent sends usage through its own telemetry export, routed to the repository's project. Terma's hooks record session boundaries, edited files, subagents, and plan usage, and append them to a local spool without touching the network.
  </Step>
  <Step title="Commits are stamped locally">
    When you commit, the hook matches staged files to sessions and adds trailers in under 50 ms. Every commit is recorded for delivery.
  </Step>
  <Step title="Events are delivered in the background">
    The spool is delivered after commits and session ends, with retry and backoff. Nothing is lost if the network is down.
  </Step>
  <Step title="You read it back">
    The dashboard shows sessions, people, models, pull requests, and where agent work lands in your codebase. `terma usage` and `terma session` answer the same questions from a terminal.
  </Step>
</Steps>
