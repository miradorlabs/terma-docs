Terma collects two kinds of data from your machine: **telemetry** exported by your coding agents, and **hook events** recorded by Terma's own hooks. Both are held to your team's collection policy, applied on your machine before anything is sent.

## Which sessions are collected

Your team's [collection policy](/concepts/collection-policy), set by an organization admin on **Team settings → Data collection**, decides which sessions leave your machine:

- **Every session** collects every session on your machine, inside a git repository or not.
- **Only the repositories listed** collects a session only inside a git working copy whose `origin` remote matches an entry on the list. An empty list collects nothing.

Each entry is `host/owner/name`, such as `github.com/acme/api`, or a longer path for GitLab subgroups. Terma normalises your `origin` before comparing, ignoring case: the host without port or credentials, the path without `.git` or a trailing slash, from `git@host:path`, `https://`, `ssh://`, and `git://` forms. A subdirectory or a linked worktree of a listed repository is collected too; a worktree reads `origin` from its main repository.

These are never collected under a repository list:

- A folder outside git, a repository with no `origin`, or an `origin` that is a local path or `file://` URL.
- A fork whose `origin` points at your own copy, such as `github.com/you/api`.
- An SSH host alias such as `git@github-work:acme/api`, which normalises to host `github-work`. Point `origin` at the real host and choose the key with `core.sshCommand` instead. `terma doctor` shows the origin terma sees.

A session that isn't collected is dropped on your machine. Its telemetry never leaves, and the hooks keep only a local note that the session is not collected. Each collected session reports to the team of the developer who ran it.

## What hooks record

Terma's hooks report structure, not conversation: session ids, file paths an agent edited, tool names, timings, models, and your plan's usage windows. Hooks do not open prompts, tool input or output, error text, or transcripts.

The one exception is Codex, whose export leaves out the assistant's replies. Terma's Codex hook reads each turn's replies from Codex's local session log so the conversation is complete. Prompts and replies travel together: they leave your machine only when your team's policy collects prompts.

## What agents export

Prompt text, model responses, and tool content reach Terma only through the agent's own telemetry export, which `terma setup` points at a relay on your machine. Your team's policy decides what the relay forwards:

| Policy setting | Effect |
|---|---|
| **Don't send prompts** | Prompt text and model responses are removed before anything leaves |
| **Don't send tool inputs and results** | Tool parameters, input, and output are removed before anything leaves |

Hook events queued on your machine are held to the same policy when they are sent: an event queued before the policy tightened leaves without the content it no longer collects, and one from a repository no longer listed does not leave. Until terma has fetched your team's policy, nothing leaves.

<Note>
  Cursor and Antigravity hooks never read prompt, response, or command text.
</Note>

## What every commit sends

With commit stamping on, `post-commit` records an event for every commit in a collected repository, so Terma can measure how much of the work agents contributed. For a commit with no agent session in it, that event carries only the commit's identity and size: SHA, remote URL, branch, file count, and lines added and deleted. File names and per-file stats are included only on commits that carry a session trailer. Merge and squash commits produce nothing.

## What stays on your machine

| Item | Where | Protection |
|---|---|---|
| Sign-in credentials and team keys | The system keychain | Protected by your operating system. With `terma setup --insecure-storage`, or when no keychain is usable, they are kept in plain text under `~/.config/terma` (`%APPDATA%\terma` on Windows), readable only by you |
| Queued events, relay state, hook state | `~/.local/state/terma` (`%LOCALAPPDATA%\terma` on Windows) | Readable only by you; the queue is bounded at 16 MB and undelivered events are dropped after 14 days |

Nothing is written into a repository's working tree or committed files. The only thing terma writes inside a repository is its two commit hooks under `.git/hooks`, when your team's policy stamps commits — git neither tracks nor commits them.

## Team API keys

A team API key belongs to one team, and what it may do is chosen when it is created. An **Ingest only** key can send telemetry into its team. It can read only its own identity (its organization, team, and permissions) and the team's collection policy, which terma needs to know what to send; it cannot read the team's sessions or metrics. A **Full access** key can also read and write the team's data, so keep one off shared machines. **Team settings → API keys** shows each key's access; revoke a key there.

## Sign-in

`terma setup` uses a browser handoff with PKCE. You approve the CLI in your browser, and a single-use code is handed to a listener on `127.0.0.1`. The code is useless without a verifier that never leaves the CLI process. `terma teardown --sign-out` revokes your sign-in on the server, not just locally.

A machine with no one to sign in, such as a CI runner or an ephemeral VM, signs in with a team server key in `TERMA_API_KEY` instead ([Headless setup](/cli/headless-setup)). Setup checks that the variable holds a team server key before sending it anywhere, keeps it as the team's key, and sends it only to the Terma host it was set up against. A kept key works until you revoke it in **Team settings → API keys**; see [Headless setup](/cli/headless-setup#after-setup) for signing a machine out.

## Hooks never get in your way

- Every hook is guarded, so a missing or broken `terma` never fails a commit.
- Hooks never make a network request; they append to a local queue, which is delivered in the background with retry and backoff.
- `prepare-commit-msg` finishes in under 50 ms.
- `TERMA_HOOKS=0` turns terma's hooks off for one shell or process.

## Limits worth knowing

- **Attribution is not authentication.** Commit trailers and agent identities attribute work among colleagues. Anyone with commit access can write a trailer by hand, so treat them as who to credit the work to, not as proof of who did it.
- **Processes running as you** can reach your credentials and keys. If you run untrusted code, run `terma teardown --sign-out`.

## Reporting a vulnerability
