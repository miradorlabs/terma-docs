Capturing sessions tells you what agents cost. Attribution tells you what that spend produced. Terma links each commit to the agent sessions that contributed to it by adding standard Git trailers to the commit message, so the link lives in your Git history where any tool can read it.

## How commits are stamped

<Steps>
  <Step title="Agent hooks record what each session edits">
    As an agent works, its hooks tell Terma which files each session touched. Terma keeps a local manifest per session.
  </Step>
  <Step title="prepare-commit-msg intersects staged files with those manifests">
    When you commit, Terma's `prepare-commit-msg` hook compares the staged files with every session's manifest. Each session that touched a staged file gets one `Agent-Session-Id` / `Agent-Tool` trailer pair.
  </Step>
  <Step title="post-commit retires the committed files">
    `post-commit` removes the committed files from the session manifests, so the next commit is not stamped for work that already landed, and records the commit for delivery to Terma.
  </Step>
</Steps>

A commit with only your own edits gets no trailer. Merges, squashes, and the commits a rebase or cherry-pick replays are never stamped.

## Commit message format

```text title="A commit with a session trailer"
feat(billing): prorate invoices on plan change

Credit the unused portion of the old plan when a customer switches mid-cycle.

Agent-Session-Id: 018f3a2c-7d4e-7a1b-9c3d-2e5f6a7b8c9d
Agent-Tool: claude-code/2.1
```

`Agent-Session-Id` is the agent's own session id — the same id you see in the dashboard. `Agent-Tool` names the agent, followed by its version when the agent reports one. The trailers follow the standard Git trailer format, so `git log --format='%(trailers)'` and the GitHub API can read them without Terma.

## Several sessions in one commit

A commit can contain work from several sessions — for example, Claude Code drafted a function and Codex wrote its tests. The hook adds one trailer pair per contributing session:

```text title="A commit with two session trailers"
feat(auth): add PKCE flow for OAuth clients

Agent-Session-Id: 018f3a2c-7d4e-7a1b-9c3d-2e5f6a7b8c9d
Agent-Tool: claude-code
Agent-Session-Id: 019a4b1d-8e5f-7b2c-0d4e-3f6a7b8c9d0e
Agent-Tool: codex
```

Edits made by a subagent are attributed to the session that spawned it, so a commit of a subagent's work carries the parent session's trailer.

## Every commit is counted

`post-commit` records an event for every commit in the repository, stamped or not, so Terma can compare agent-assisted work with the rest. For a commit without a session, the event carries only its identity and size — SHA, remote URL, branch, file count, and line totals — never file names. See [Privacy and security](/concepts/privacy#what-every-commit-sends).

## Fast, local, and safe

- `prepare-commit-msg` reads local manifests only and makes no network call. It finishes in under 50 ms.
- Events are appended to a local queue and delivered in the background after the commit, with retry and backoff.
- Every hook is guarded: a missing or broken `terma` never fails a commit.
- `TERMA_HOOKS=0` turns terma's hooks off for one shell or process.

## Setting it up

Commit stamping is your team's choice. An organization admin turns on **Stamp commits with the agent session** on **Team settings → Data collection**. Each developer runs `terma setup` once; there is nothing to commit.

With stamping on, the first agent session in a repository your team collects installs `prepare-commit-msg` and `post-commit` into that repository's own `.git/hooks` (the shared one, so linked worktrees use them too). git neither tracks nor commits these files. A repository no agent has worked in, and a folder outside git, get nothing.

terma chains to hooks already there: an existing hook is renamed `<name>.pre-terma` and still runs first, unchanged. It keeps its veto — if it exits non-zero, the commit stops.

- **pre-commit** and **lefthook** work normally, because terma doesn't set `core.hooksPath`.
- **husky v9** sets the repository's own `core.hooksPath`, so git never reads `.git/hooks`. terma skips such a repository, and `terma doctor` reports that its commits are not stamped.

terma never removes these hooks. Turning stamping off only stops terma adding them anywhere new, and `terma teardown` leaves them too — with terma gone, they only run the hook each one displaced.

```bash
terma doctor     # in the repository: reports whether its commits are stamped
```

<Note>
  Trailers attribute work among colleagues; they are not proof of authorship. Anyone with commit access can write a trailer by hand.
</Note>
