Capturing sessions tells you what agents cost. Attribution tells you what that spend produced. Terma links each commit to the agent sessions that contributed to it by adding standard Git trailers to the commit message, so the link lives in your Git history where any tool can read it.

## How commits are stamped

<Steps>
  <Step title="Agent hooks record what each session edits">
    As an agent works, its hooks tell Terma which files each session touched. Terma keeps a local manifest per session.
  </Step>
  <Step title="prepare-commit-msg intersects staged files with those manifests">
    When you commit, Terma's `prepare-commit-msg` hook compares the staged files with every session's manifest. Each session that touched a staged file gets one `Agent-Session-Id` / `Agent-Tool` trailer pair.
  </Step>
  <Step title="post-commit retires the committed files">
    `post-commit` removes the committed files from the session manifests, so the next commit is not stamped for work that already landed, and records the commit for delivery to Terma.
  </Step>
</Steps>

A commit with only your own edits gets no trailer. Merge and squash commit messages are never modified.

## Commit message format

```text title="A commit with a session trailer"
feat(billing): prorate invoices on plan change

Credit the unused portion of the old plan when a customer switches mid-cycle.

Agent-Session-Id: 018f3a2c-7d4e-7a1b-9c3d-2e5f6a7b8c9d
Agent-Tool: claude-code/2.1
```

`Agent-Session-Id` is the agent's own session id — the same id you see in `terma session list` and in the dashboard. `Agent-Tool` names the agent, followed by its version when the agent reports one. The trailers follow the standard Git trailer format, so `git log --format='%(trailers)'` and the GitHub API can read them without Terma.

## Several sessions in one commit

A commit can contain work from several sessions — for example, Claude Code drafted a function and Codex wrote its tests. The hook adds one trailer pair per contributing session:

```text title="A commit with two session trailers"
feat(auth): add PKCE flow for OAuth clients

Agent-Session-Id: 018f3a2c-7d4e-7a1b-9c3d-2e5f6a7b8c9d
Agent-Tool: claude-code
Agent-Session-Id: 019a4b1d-8e5f-7b2c-0d4e-3f6a7b8c9d0e
Agent-Tool: codex
```

Edits made by a subagent are attributed to the session that spawned it, so a commit of a subagent's work carries the parent session's trailer.

## When an agent cannot report files

If an agent's hooks cannot report which files it edited, a session that was recently active in the repository can still claim the commit, within a four-hour window. Agents that report files precisely are always matched by file.

## Every commit is counted

`post-commit` records an event for every commit, stamped or not, so Terma can compare agent-assisted work with the rest. For a commit without a session, the event carries only its identity and size — SHA, remote URL with credentials removed, branch, author, file count, and line totals — never file names. See [Privacy and security](/concepts/privacy#what-every-commit-sends).

## Fast, local, and safe

- `prepare-commit-msg` reads local manifests only and makes no network call. It finishes in under 50 ms, a budget enforced in CI.
- Events are appended to a local spool and delivered in the background after the commit, with retry and backoff.
- Every hook ends in `|| true`: a missing or broken `terma` never fails a commit.

## Setting it up

`terma install` writes the commit hooks — through husky, lefthook, or pre-commit if the repository uses one — along with the agents' hooks, into files you commit. Once they are merged, everyone who works in the repository with Terma installed gets their commits attributed.

```bash
terma install    # in the repository
terma doctor     # makes a real scratch commit and checks it is stamped
```

<Note>
  Trailers attribute work among colleagues; they are not proof of authorship. Anyone with commit access can write a trailer by hand.
</Note>

## Where attribution shows up

- **`terma session git`** lists the branches, commits, pushes, and pull requests a session's tool calls produced.
- **The dashboard** shows each session's git activity, the pull requests agents contributed to, and a burn map of where agent work lands in your codebase. See [Pull requests](/dashboard/pull-requests) and [Burn map](/dashboard/burn-map).
