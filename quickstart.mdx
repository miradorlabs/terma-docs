This guide takes you from a new account to your first agent session in Terma. You will create an organization and a project, install the `terma` CLI, set up a repository, and verify that sessions and commit trailers are flowing.

<Steps>
  <Step title="Create your account">
    Sign up at [terma.ai/sign-up](https://terma.ai/sign-up) with Google, GitHub, or an email address.

    Terma is in private beta. If you are asked to **Enter your invite code**, enter the code from your invite — for example `terma-7kq4-m2xp`. If an organization invited you by email, you don't need a code.

    Then **Name your organization** — use your company or team name — and optionally invite your teammates by email. You can do both later from **Settings → Organization**.
  </Step>

  <Step title="Create a project">
    On your organization's home page, select **Create a project**. Give it a name, such as the product or team it covers, tick **Development**, and select **Create project**.

    Terma opens a setup guide, **Bring your first session into view**. Choose **Claude Code, Codex, Cursor, Pi, etc.** — the path for coding agents — and keep the page open: it listens for your first session.

    <Tip>
      Connecting a router such as OpenRouter, or another tool that exports OpenTelemetry? Choose **Other** instead. See [OpenRouter](/integrations/openrouter).
    </Tip>
  </Step>

  <Step title="Install the CLI">
    <CodeGroup>
      ```bash Install script
      curl -fsSL https://terma.ai/install.sh | bash
      ```

      ```bash Homebrew
      brew tap miradorlabs/tap
      brew trust miradorlabs/tap
      brew install terma
      ```

      ```bash npm
      npm install -g @miradorlabs/terma
      ```
    </CodeGroup>

    Every method verifies the release checksum before installing. Check that `terma` is on your `PATH`:

    ```bash
    terma --version
    ```
  </Step>

  <Step title="Install Terma in your repository">
    From inside the repository you work in:

    ```bash
    terma install
    ```

    `install` walks you through everything:

    1. **Sign in.** Your browser opens on **Authorize the Terma CLI**. Choose your organization and select **Authorize**, then return to your terminal.
    2. **Choose your agents** — Claude Code, Codex CLI, or Codex Desktop.
    3. **Choose the project** you just created. If your organization has only one project, it is chosen for you.
    4. **Confirm the hooks** it offers to write.

    It finishes with a checklist and numbered next steps. Follow them — usually, reload your shell so the agent shims are on your `PATH`, then commit the files it lists:

    ```bash
    source ~/.zshrc    # or open a new terminal
    git add .terma .claude/settings.json    # the files install lists, such as .codex/hooks.json for Codex
    git commit -m "chore: install terma"
    ```

    <Note>
      Using Codex? Trust Terma's hooks once: run `/hooks` in Codex CLI, or open **Settings → Hooks → Review** in Codex Desktop. See [Codex](/integrations/codex#trust-the-hooks).
    </Note>
  </Step>

  <Step title="Start a session">
    Restart any agent that was already running, then start a new session in the repository and give it a task. Within a minute or two, the setup guide shows **First session received**.

    Verify the whole chain from your terminal:

    ```bash
    terma doctor
    ```

    `doctor` checks every link — sign-in, binding, hooks, agent export, shell routing — makes a scratch commit in a temporary worktree to prove trailers are stamped, and confirms events reach Terma. Every failure names the command that fixes it.

    Then read your first numbers:

    ```bash
    terma usage --since today
    terma session list --since today
    ```
  </Step>

  <Step title="Bring your team">
    Push the files `terma install` wrote and merge them. After that, each teammate installs the CLI and runs `terma install` in the repository once. It sets up their own sign-in, keys, and agent routing without rewriting the committed files.
  </Step>
</Steps>

When your agent makes a commit, the commit message carries the session that produced it:

```text
feat(billing): prorate invoices on plan change

Credit the unused portion of the old plan when a customer switches mid-cycle.

Agent-Session-Id: 018f3a2c-7d4e-7a1b-9c3d-2e5f6a7b8c9d
Agent-Tool: claude-code/2.1
```
