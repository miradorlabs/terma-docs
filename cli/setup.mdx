`terma setup` gets a machine ready to use Terma. It does two things and nothing more — it binds no project, configures no telemetry, and writes no repository files:

1. **Signs you in.** Your browser opens on Terma, you choose an organization and approve the CLI, and a single-use code is handed back to a listener on `127.0.0.1`. A sign-in you already approved is reused.
2. **Records which coding agents you use**, so [`terma install`](/cli/install) never has to ask again.

`setup` is optional. `terma install` signs you in and asks for your agents itself when you have not run it. The real configuration — pointing an agent at a project and wiring hooks — happens per repository, in `terma install`.

## Usage

```bash
terma setup
```

On a terminal, setup shows a checklist:

```text
Which coding agents do you use? (space toggles, enter confirms)
```

Agents it finds installed on your machine, or that you recorded before, are preselected. The available choices are:

| Choice | Notes |
|---|---|
| **Claude Code** | Telemetry and commit attribution |
| **Codex CLI** | The `codex` shell command |
| **Codex Desktop** | The desktop app, which uses a separate capture path — see [Codex](/integrations/codex#codex-desktop) |

Cursor, OpenCode, and Antigravity appear in the list marked **Coming Soon** and cannot be selected yet. See [Integrations](/integrations/cursor) for what is available for them today.

When setup finishes, it prints the agents it recorded and the next step:

```text
Agents recorded: Claude Code, Codex.

Done! Now run `terma install` in each codebase you want to instrument with terma.
```

## Flags

| Flag | Description |
|---|---|
| `--harness <list>` | Comma-separated agents to record, skipping the picker: `claude`, `codex`, `codex-desktop` |
| `-y`, `--yes` | Skip the picker and record every available agent installed on this machine |
| `--no-browser` | Print the sign-in URL instead of opening a browser |

```bash title="Non-interactive setup"
terma setup --harness claude,codex --no-browser
```

## What gets stored

Setup writes only to your Terma configuration directory, `~/.config/terma/`:

- `credentials.json` — your organization-scoped CLI credential, readable only by you (`0600`)
- `config.json` — your profile, organization, and the agents you chose

Nothing is written to any repository and no agent's settings are changed.

## Next steps

Run `terma install` in each repository you want to report to Terma, then check the result:

```bash
cd your-repo
terma install
terma doctor
```

<Note>
  If you chose **Codex Desktop**, approve Terma's hooks in the app after running `terma install` in a repository: open **Settings → Hooks → Review** in Codex Desktop and approve the Terma entries.
</Note>
