A Terma project is where your agents' sessions, usage, and attributed commits land. Each repository is bound to one project by [`terma install`](/cli/install), and the binding is saved in the committed `.terma/settings.json`. There is no global "current project": the project always comes from the repository you are in.

## How the project is chosen

Every project-scoped command — `terma usage`, `terma session`, `terma principal`, `terma connect` — resolves the project in this order:

1. `--project <id>` (or `-p`) on the command line
2. The `TERMA_PROJECT_ID` environment variable
3. The binding in the current repository's `.terma/settings.json`, found from any subdirectory

An explicit `--project` or `TERMA_PROJECT_ID` applies to that command only and never changes the saved binding.

```bash title="Read another project without changing anything"
terma usage --since 7d --project 3f594407-aec5-4ab7-9d7b-9e4ebe5822f0
terma session list --project 3f594407-aec5-4ab7-9d7b-9e4ebe5822f0
```

Outside an installed repository, pass `--project` to read project data.

## Changing a repository's project

Run `terma install` again. With several projects in your organization, it asks you to choose, offering the current binding first. Or name the project directly:

```bash
terma install --project "Payments API"
```

Commit the updated `.terma/settings.json` so your teammates report to the same project.

## terma project list

Lists the projects in the current organization.

```bash
terma project list
```

Names are shown without ids. Use `-o json` to see ids, or when two projects share a name.

## terma project show

Shows the project the current repository is bound to.

```bash
terma project show
```

`terma project` is an advanced command: it works as documented but is not listed in `terma --help`.

## The binding file

`.terma/settings.json` names the project and records what `terma install` wired. It contains no secrets.

```json .terma/settings.json
{
  "project": {
    "id": "3f594407-aec5-4ab7-9d7b-9e4ebe5822f0",
    "name": "Payments API",
    "organization_id": "88dd0f5c-c288-4384-9dc6-9713281ad1ed"
  },
  "install": {
    "hook_manager": "git",
    "hooks": ["prepare-commit-msg", "post-commit"],
    "terma_version": "1.4.0",
    "installed_at": "2026-09-11T17:27:09Z"
  }
}
```

## Worktrees

A linked Git worktree — including the ones coding agents create for isolated work — uses its own `.terma/settings.json` when it has one, and otherwise its main checkout's. Everything from a worktree reports as its main repository, with an attribute naming the worktree. `terma status` and `terma doctor` say when a worktree is bound through its main checkout.

<Note>
  If you keep `.terma/settings.json` out of Git, tools that create worktrees from tracked files only will not copy it. Codex-managed worktrees, for example, need the file listed in `.worktreeinclude`.
</Note>
