The Terma CLI (`terma`) is a single static binary with no runtime dependency. Pick the installation method that fits your workflow, then make sure `terma` is on your `PATH` — the hooks Terma installs call it by name.

## Install the CLI

<CodeGroup>

```bash Homebrew
brew tap miradorlabs/tap
brew trust miradorlabs/tap     # once; Homebrew will not load an untrusted tap
brew install terma
```

```bash Install script
curl -fsSL https://terma.ai/install.sh | bash
```

```bash npm
npm install -g @miradorlabs/terma
```

</CodeGroup>

Every method downloads the same release and verifies it against the release's `checksums.txt` before anything is run.

### Install script options

The install script is POSIX `sh`, so `| sh` works too. It picks the archive for your platform, verifies the checksum, and places the binary in `/usr/local/bin` or `~/.local/bin`. Two environment variables change its behavior:

| Variable | Effect |
|---|---|
| `TERMA_INSTALL_DIR` | Install the binary to this directory instead |
| `TERMA_VERSION` | Install a specific release, for example `TERMA_VERSION=v1.2.3` |

### Direct download or source

Native binaries for macOS, Linux, and Windows are published on [GitHub Releases](https://github.com/miradorlabs/terma-cli/releases) with checksums and signed provenance. To build from source, clone the repository and run `make install`.

<Note>
  A source build reports `dev` (or its `git describe`) as its version and is never updated automatically. Run `terma update --force` to switch it to the latest published release.
</Note>

## Verify the installation

```bash
terma --version
```

<Warning>
  **`terma` must be on your `PATH`.** Every committed hook is a guarded one-liner that runs `terma hook <event>` only when `command -v terma` finds the binary. If `terma` is not on your `PATH`, hooks exit quietly: nothing fails, but no commits are stamped and no events are recorded. `terma doctor` checks this first and prints the command that fixes it.
</Warning>

## Keep it up to date

Terma checks for new releases once a day after interactive commands and prints a notice when one is available. Run `terma update` to install it, or `terma update --auto on` to install future releases automatically. See [`terma update`](/cli/update).

## System requirements

- **Operating system:** macOS or Linux (x86_64 or arm64). Windows binaries are available from GitHub Releases.
- **Runtime:** none — the binary is self-contained.
- **Git:** required for commit hooks and attribution. Agent hooks and telemetry also work in folders that are not Git repositories.

## Remove the CLI

`terma uninstall` removes what `terma install` wrote to one repository; it does not remove the binary. To remove the binary, use the method you installed with, for example `brew uninstall terma` or `npm uninstall -g @miradorlabs/terma`.
