`terma usage` answers questions like "how much did Ada use today?" It sums the tokens and provider cost of every model call that settled inside a time window, whichever session it belonged to. By default it covers the last 24 hours, grouped by user.

## Usage

```bash
terma usage [flags]
```

```bash title="Examples"
terma usage --user ada --since today
terma usage --group-by model --since 7d
terma usage --source codex --since yesterday --until today
terma usage --group-by api-key --since 30d
```

Like every insight command, `usage` reads the project bound to the current repository. Outside a repository, or to read another project, pass `--project <id>`.

## Output

```bash title="terma usage --since today"
$ terma usage --since today

claude-code  Priya         b31e0d9c77a24f18  7.4400    966138   119922  8413746     246140       9745946       86
codex        Ada           7c5c8f2e1a9b4d03  5.9220    1142646  52872   3672026     0            4867544       37
openrouter   (no user id)                    1.2840    1872240  144066  0           0            2016306       127
TOTAL                                        33.5640   5325679  467224  25063089    685932       31541924      327
```

When grouped by user or API key, each row is one principal within one source, so the same person can appear once per agent. `COST USD` is the provider's price for those calls. Cache reads and writes are reported separately because providers bill them at different rates; `TOTAL TOKENS` is the sum of all four token columns.

If nothing settled in the window, `usage` prints `No usage recorded for this window and filter.` That is a valid answer, not an error.

## Flags

| Flag | Description |
|---|---|
| `--since <time>` | Window start. Default: 24 hours ago. |
| `--until <time>` | Window end. Default: now. |
| `--group-by <dimension>` | `user` (default), `api-key`, `source`, `model`, `provider`, or `none` |
| `--user <name>` | A person by name, email, alias, or id. Repeatable. |
| `--api-key <name>` | An API key by label, alias, or id — never the secret. Repeatable. |
| `--source <source>` | A source system, such as `claude-code` or `codex`. Repeatable. |
| `--model <model>` | Only calls made with this model. Repeatable. |
| `--provider <provider>` | Only calls to this model provider. Repeatable. |

Repeat a filter flag to match any of its values.

### Time formats

`--since` and `--until` accept:

- an RFC 3339 timestamp, such as `2026-09-09T09:00:00Z`
- a date, such as `2026-09-09`
- a relative age, such as `90s`, `15m`, `2h`, or `7d`
- `today`, `yesterday`, or `now` — `today` and `yesterday` are local midnights

The window is half-open: it includes `--since` and excludes `--until`.

## Matching people

`--user` takes a name, email, alias, or id and resolves it through the [principal catalog](/cli/principals). One person is often several principals — the same email seen by Claude Code and by Codex — and a name match returns all of them, so the answer covers every agent they use.

A partial name that matches two different people is an error that names both, for example `"da" matches several principals (Dana, dawson@example.com)`. Nothing is queried; use the full email, the alias, or the id.

Traffic attributed to an API key rather than a person — OpenRouter calls, for example — shows as `(no user id)`. Run `terma usage --group-by api-key` to see which key it came from.

## What the numbers mean

`usage` reads counters that the platform derives from every model call that has **settled**. A session that started yesterday and ran past midnight contributes only today's portion to `--since today`.

- The counters are sampled over time, so the window's edges are interpolated to the nearest samples. A figure can differ slightly from a hand-sum of session totals.
- A model call that has not settled yet is not counted until it does.
- The JSON output includes the resolved window bounds in UTC and the exact queries it ran.

`usage` and `terma session list` answer different questions. Use `usage` for "how much in this period?" and [`session list`](/cli/sessions) for "which conversations, and what did each cost?" Because a session's totals cover its whole life, the two legitimately disagree whenever a session straddles the window's edge.
