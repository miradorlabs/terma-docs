A session is one conversation with a coding agent — Claude Code, Codex, or another connected source — rolled up with its token usage, cost, tool calls, and git activity. The `terma session` commands list sessions, show one session's totals, replay its events, and show the commits and pull requests it produced.

A session is identified by its **session id together with its source system**, so `get`, `events`, and `git` take both. Copy them from `terma session list`.

## terma session list

Lists the project's sessions with their lifetime usage, most recently active first.

```bash
terma session list [flags]
```

```bash title="Examples"
terma session list --user ada --since yesterday --until today
terma session list --source codex --model gpt-5 --all
terma session list --provider anthropic --sort cost --page-size 20
terma session list --filter 'api_key_id="30692719"'
terma session list --follow
```

The table shows `SOURCE`, `USER`, `STARTED`, `LAST ACTIVE`, `TURNS`, `TOOLS`, `TOKENS`, `COST USD`, `MODELS`, and `SESSION ID`. In JSON, each session also carries its git counters (commits, pushes, pull requests, files touched), the repositories it touched, and user and API key names alongside their ids.

| Flag | Description |
|---|---|
| `--since <time>` | Sessions last active at or after this time |
| `--until <time>` | Sessions last active before this time |
| `--user <name>` | A person by name, email, alias, or id. Repeatable. |
| `--api-key <name>` | An API key by label, alias, or id. Repeatable. |
| `--source <source>` | A source system, such as `claude-code` or `codex`. Repeatable. |
| `--model <model>` | Sessions that used this model. Repeatable. |
| `--provider <provider>` | Sessions that used this model provider. Repeatable. |
| `-f`, `--filter <expr>` | An extra [AIP-160](https://google.aip.dev/160) expression over `source_system`, `user_id`, `api_key_id`, `model`, and `provider`, combined with the other filters |
| `--sort <key>` | Rank by `recency` (default), `cost`, `tokens`, `turns`, or `tools`, highest first |
| `--page-size <n>` | Sessions per page, 1–1000 (default 100) |
| `--page <n>` | Page number, counting from 1 |
| `--all` | Follow every page |
| `--follow` | Tail the live list until interrupted |

<Note>
  `--since` and `--until` select by when a session was **last active**, not when it started. A session that began last week and ran this morning is inside `--since today`. For spend inside a calendar window, use [`terma usage`](/cli/usage).
</Note>

`--until` is applied by the CLI rather than the server, so it cannot be combined with `--page`; use `--all` or a larger `--page-size` instead.

## terma session get

Shows one session's roll-up: the same totals a `session list` row carries.

```bash
terma session get <session-id> --source claude-code
```

| Flag | Description |
|---|---|
| `--source <source>` | The session's source system, such as `claude-code` (required) |

## terma session events

Replays a session's events, oldest first: prompts, model calls with their usage, tool calls and results, compactions, and errors. Alias: `terma session replay`.

```bash
terma session events <session-id> --source claude-code [flags]
```

```bash title="Examples"
terma session events <session-id> --source claude-code --tools-only
terma session events <session-id> --source claude-code --errors-only
terma session events <session-id> --source claude-code --kind model_call --kind compaction
terma session events <session-id> --source claude-code --since 2026-09-09T09:00:00Z --until 2026-09-09T10:00:00Z
```

The table shows `TIME`, `KIND`, `TOOL / MODEL`, `STATUS`, `TOKENS`, `COST USD`, and `CONTENT`, with each event's content folded to one line.

| Flag | Description |
|---|---|
| `--source <source>` | The session's source system (required) |
| `--kind <kind>` | Keep only these kinds. Repeatable: `session_start`, `turn_start`, `user_message`, `assistant_message`, `model_call`, `tool_call`, `tool_result`, `tool_decision`, `compaction`, `error` |
| `--tools-only` | Keep tool calls, results, and decisions |
| `--tool <name>` | Keep only events for this tool |
| `--errors-only` | Keep errors and failed events |
| `--since <time>`, `--until <time>` | Keep events inside this window |
| `--content-width <n>` | Characters of content per table row (default 80; `0` for all) |

Content is whatever the agent was configured to export. A session from an agent set up with `--prompts off` or `--exclude-tool-content` carries none of that content. JSON output is verbatim.

## terma session git

Lists the branches, commits, pushes, and pull requests an agent's tool calls produced during a session. This is evidence of actions the agent took — not a deduplicated commit ledger.

```bash
terma session git <session-id> --source claude-code
terma session git <session-id> --source claude-code --follow
```

The table shows `TIME`, `ACTION`, `OUTCOME`, `REPOSITORY`, `REF`, `COMMIT / PR`, and `MESSAGE`.

| Flag | Description |
|---|---|
| `--source <source>` | The session's source system (required) |
| `--follow` | Tail live updates until interrupted |

## Live tails

`session list --follow` and `session git --follow` stream updates. As a table, each update is one line; as JSON, each is one newline-delimited object.

- `session list --follow` repeatedly sends the whole first page of the list with your filters. The CLI prints only sessions that are new or changed.
- `session git --follow` sends `upsert` events keyed by `activity_id`; replace your copy of an activity on each one.

The server closes a live connection after an hour. Rerun the command to reconnect.

## Common errors

| Message | Meaning |
|---|---|
| `no claude-code session "…" in this project` | Wrong session id, wrong `--source`, or wrong project |
| `the gateway sent no summary of the session within 15s` | `session get` reached the server but got no answer; rerun |
| `--until is applied after the server pages the list …` | `--until` cannot be combined with `--page`; use `--all` or a larger `--page-size` |
| `INVALID_FILTER` | The `--filter` expression was rejected; the message names the rule |
| `the server closed the stream (connections rotate hourly)` | Normal for `--follow`; rerun |
