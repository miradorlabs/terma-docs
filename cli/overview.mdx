The Terma CLI (`terma`) connects your coding agents to Terma, then stamps the commits they produce so agent spend can be traced to the code it shipped.

It is deliberately small. You install it, run `terma setup` once, and you are done: there is no per-repository step, no file to commit, and nothing to configure per project. Your team's collection policy, set in Terma, decides which repositories are collected.

## Four commands

| Command | When | What it does |
|---|---|---|
| [`terma setup`](/cli/setup) | Once per developer | Signs you in, chooses your team and coding agents, and writes machine-wide hooks. Run it again to switch team or organization, or to repair the machine. A machine with no browser signs in with a [team server key](/cli/headless-setup). |
| [`terma doctor`](/cli/doctor) | Any time | Verifies the whole chain end to end. Every failure names its fix, usually `terma setup` again. |
| [`terma update`](/cli/update) | When a release is out | Installs the latest release and refreshes what terma installed. |
| [`terma teardown`](/cli/teardown) | To leave | Undoes setup on this machine. `--sign-out` also signs you out. |

Every command is safe to run again.

```bash
curl -fsSL https://terma.ai/install.sh | bash
terma setup
terma doctor
```

Restart any coding agent that was already running after `terma setup`, so it loads the new configuration.

`terma` has a few more commands that other programs run for it: your agents and git run `terma hook`, the relay's background service runs `terma relay`, and the hooks deliver their queue with `terma spool`. They are hidden from `terma --help`, and you never need to run them yourself.

## How it fits together

<Steps>
  <Step title="Your team chooses what is collected">
    An organization admin sets the team's collection policy in Terma (**Team settings → Data collection**): every session, or only the repositories it lists, and whether prompts and tool content are included.
  </Step>
  <Step title="Setup wires your machine once">
    `terma setup` points your agents' telemetry at a relay terma runs on `127.0.0.1` and writes their machine-wide hooks. It does not touch git's configuration and writes nothing into a repository's files.
  </Step>
  <Step title="Your agents work as usual">
    A hook claims each session in a repository your team collects. The relay forwards only those sessions, with only the content the policy allows. Everything else never leaves your machine.
  </Step>
  <Step title="Commits are stamped">
    When the policy asks for commit stamping, the first agent session in a collected repository adds two git hooks to its `.git/hooks`. Commits of files an agent edited get `Agent-Session-Id` and `Agent-Tool` trailers.
  </Step>
</Steps>

## Global flags

| Flag | Description |
|---|---|
| `-t`, `--team` | Team for this command (default: the team chosen at setup) |
| `-o`, `--output` | Output format: `table`, `json`, `yaml`, or `csv` |
| `--profile` | Configuration profile to use |
| `-v`, `--version` | Print the version |
