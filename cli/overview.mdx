The Terma CLI (`terma`) connects coding agents to Terma, then stamps the commits they produce so agent spend can be traced to shipped code. It is also how you read that activity back from a terminal — or from an agent shelling out to `terma`.

## The workflow

Terma has two onboarding commands with different owners, then two that tell you whether it worked:

| Command | Run it | What it does |
|---|---|---|
| [`terma setup`](/cli/setup) | Once per developer (optional) | Signs you in and records which coding agents you use. It binds no project and writes no repository files. |
| [`terma install`](/cli/install) | Once per repository | Binds the repository to a Terma project, routes your agents to it, and offers to install commit and agent hooks. |
| [`terma status`](/cli/status) | Any time | A quick, local view of sign-in, binding, hooks, agents, and queued events. |
| [`terma doctor`](/cli/doctor) | After installing, or when something looks wrong | Verifies the whole chain end to end, including a scratch commit. |

```bash
terma setup       # optional: sign in and choose agents
terma install     # run inside each repository
terma doctor      # verify the chain end to end
```

## Commands

`terma --help` lists the commands you need day to day:

```text
setup       Sign in and choose your coding agents (once per developer)
install     Configure this workspace: point your agents at its project and wire the hooks
status      Show connections, queued events, and setup readiness
doctor      Verify the whole chain end to end and report setup readiness
session     List and inspect the coding sessions your agents ran
usage       Sum token usage and cost over a time window, by person, agent or model
org         List and switch between your organizations
uninstall   Remove everything terma install wrote to this repository
update      Check for updates, install the latest release, or configure automatic updates
```

Advanced commands for automation and troubleshooting are hidden from `--help` but fully supported: `login`, `logout`, `whoami`, `project`, `principal`, `connect`, `disconnect`, `harness`, `spool`, `config`, and `desktop`. Run `terma <command> --help` on any of them for details.

## Global flags

These flags work on every command:

| Flag | Description |
|---|---|
| `-o`, `--output` | Output format: `table`, `json`, `yaml`, or `csv` |
| `-p`, `--project` | Project override for this command (default: the current repository's binding) |
| `--profile` | Configuration profile to use |
| `-v`, `--version` | Print the version |

## Output formats

In a terminal, commands print human-readable tables. When stdout is not a terminal — piped to another command, or run by a script or an agent — output switches to JSON automatically, so you never need `-o json` in CI.
