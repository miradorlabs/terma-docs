Sessions and usage carry principal ids, never names. The principal catalog maps each id to the name the provider reported — a user's email, or an API key's label — and to any alias set in the Terma web app.

Every `--user` and `--api-key` flag on [`terma usage`](/cli/usage) and [`terma session`](/cli/sessions) accepts a name as well as an id and resolves it through this catalog, so you rarely need these commands directly. Use them when a match is ambiguous, or to see what the catalog knows.

`terma principal` is an advanced command: it works as documented but is not listed in `terma --help`.

## What is a principal?

A principal is an identity observed by one source: a user seen by Claude Code, a user seen by Codex, or an API key seen by OpenRouter. The same person is often several principals — for example, the same email seen by Claude Code and by Codex, whose user ids live in different namespaces. A name or email match returns all of them, so `terma usage --user ada` covers every agent Ada uses.

## terma principal find

Finds the principals matching a name, email, alias, or id.

```bash
terma principal find <name-or-id> [--kind user|api_key]
```

Matching works the way `--user` does: an exact id first, then an exact name or alias (case-insensitive), then a unique substring. Several principals sharing one name — the same person seen by two agents — count as one match.

```bash
terma principal find ada
```

## terma principal list

Lists every user and API key the project has seen.

```bash
terma principal list [--kind user|api_key] [--source claude-code]
```

The table shows `SOURCE`, `KIND`, `NAME`, `ALIAS`, and `ID`.

## When to use them

- **A name matches several people.** `terma usage --user da` fails with `"da" matches several principals (Dana, dawson@example.com)`. Use `principal find` to see the candidates, then pass the full email, the alias, or the id.
- **Usage shows `(no user id)`.** That traffic is attributed to an API key rather than a person. Run `terma usage --group-by api-key` or `terma principal list --kind api_key` to see which key.
- **Checking a teammate's identities.** Confirm that a person's Claude Code and Codex principals both resolve to the name you expect.

<Note>
  The catalog is read-only from the CLI. To give a principal a friendlier name — for example, to label an OpenRouter key with the person who owns it — set an alias in the web app under your project's **Settings → Principals**.
</Note>
