Your CLI credential is scoped to an **organization**, not a project. Projects are chosen per repository by [`terma install`](/cli/install), so you can move between repositories and projects without signing in again. A profile keeps one credential for each organization you sign into.

`terma setup` and `terma install` sign you in when needed, so most people never run `terma login` directly. `terma org` is listed in `terma --help`; `login`, `logout`, and `whoami` are advanced commands that are hidden from it but fully supported.

## terma login

Signs this machine in to one of your organizations.

```bash
terma login [flags]
```

If this profile already holds a working credential for the organization, nothing new is minted and no browser opens. Otherwise your browser opens on Terma's CLI approval page, you choose an organization and approve, and a single-use code is handed back to a listener on `127.0.0.1`. The exchange uses PKCE, so the code is useless to anyone without the verifier held by the CLI process.

| Flag | Description |
|---|---|
| `--org <name-or-id>` | Sign in to, or switch to, a particular organization (default: the current one) |
| `--force` | Always open the browser and mint a new session; the session it replaces for that organization is revoked |
| `--label <name>` | Name shown for this session (default: the hostname) |
| `--no-browser` | Print the authorization URL instead of opening a browser |

Credentials are stored in `~/.config/terma/credentials.json`, readable only by you.

## terma logout

Revokes every session this profile holds — one per organization you signed into — on the server, then deletes the local credentials.

```bash
terma logout
```

Revoking on the server is what makes this meaningful: deleting the local file alone would leave live tokens that anyone holding a copy could keep using.

## terma whoami

Shows the identity and scope of the current credential.

```bash
terma whoami
```

The output includes the profile, the API and auth endpoints, the credential type, your user, the organization, the project from the current repository's binding (or `(no repository project)`), and how many other organizations this profile is signed into.

## terma org list

Lists the organizations you belong to, with your role in each and whether this profile is signed in to it.

```bash
terma org list
```

Organization names are shown without ids. Use `terma org list -o json` to see ids, or when two organizations share a name.

## terma org use

Makes an organization the current one.

```bash
terma org use [name-or-id] [--no-browser]
```

A session this profile already holds for that organization is reused and verified; otherwise your browser opens with the organization preselected. With no argument on a terminal, `org use` shows a picker you navigate with the arrow keys.

<Note>
  Switching organizations never changes a repository's project binding. To choose a project for a repository, run `terma install` in it.
</Note>

## Headless and CI use

In CI or on a headless machine, set `TERMA_API_KEY` to a project server key instead of signing in. See [Configuration](/cli/configuration#environment-variables).
