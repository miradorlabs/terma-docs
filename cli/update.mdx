`terma update` downloads the latest published release for your platform, verifies its checksum, and replaces the binary in place. Your hooks keep working throughout.

## Usage

```bash
terma update                # install the latest release, or refresh what terma installed
terma update --check        # check without installing
terma update --auto on      # install future releases automatically
terma update --auto status  # show the saved preference
terma update --auto off     # return to notices only
```

## Flags

| Flag | Description |
|---|---|
| `--check` | Check for a newer release without installing it |
| `--auto on\|off\|status` | Turn automatic updates on or off, or show the current setting (default: `off`) |
| `--force` | Replace a source or development build with the latest published release |

## Automatic updates

Interactive commands check for a newer release once a day and print a notice when one exists. With `terma update --auto on`, terma installs it for you after a successful interactive command.

Automatic updates apply to a copy installed with the install script or downloaded from GitHub Releases, on macOS and Linux. They never run inside agent hooks, scripts, or CI. Set `TERMA_NO_UPDATE_CHECK=1` to turn off the daily check; `terma update` still works.

## Homebrew and npm installs

<Warning>
  **Homebrew does not update terma automatically**, and neither does npm, even with `--auto on`. A copy a package manager owns only gets the notice. Run `terma update` when you see it.
</Warning>

`terma update` upgrades through the package manager that owns the copy of terma you are running, not whichever one is first on your `PATH`:

| Installed with | `terma update` runs |
|---|---|
| Homebrew | `brew upgrade terma` |
| npm (global) | `npm install -g @miradorlabs/terma@latest` |

If terma is a dependency inside a project's `node_modules`, `terma update` prints the `npm install @miradorlabs/terma@latest` command for that project and runs nothing.

If you want terma to keep itself current without thinking about it, install it with the [install script](/cli/installation) instead.

## What happens after an update

Once the new binary is in place, `terma update` also refreshes what earlier versions wrote on this machine: your agents' wrapped status line and plugins, and the relay's background service. It keeps every choice you made at setup, works only from what is on disk, signs in to nothing, and never adds a file.

Already on the latest release, `terma update` runs just that refresh, so it is safe to run again.

<Note>
  Source builds are never updated automatically. Use `terma update --force` to switch one to the latest published release.
</Note>
